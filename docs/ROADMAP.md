# Этапы и приёмка

## 0. Концепция

Общий Telegram-рантайм, несколько ботов и групп/каналов, доступ из разных проектов и клиентов, публикации и инспекция по запросу человека. Без hardcode адресатов, токенов и моделей. MCP — базовый интерфейс; нативные плагины включают skill и запуск того же сервера.

## 1. Реализованное ядро — 0.2

Реестр, запись по явному адресату, CLI/MCP, Bot API adapter, текст/редактирование, фото/документы по URL/file_id, delete/pins, inspection, архив, polling, статистика и audit. Локальные тесты проверяют изоляцию, повторы, concurrency, сбои, offsets и настоящий MCP stdio. Собранный entrypoint должен работать без node_modules.

В 0.2 реализованы saved credentials, редактируемые описания и политики по Git/directory. Для одного bot/channel через MCP и реальный Bot API проверены текст, replay/conflict, edit, pin/unpin, delete, архив/audit и блокировка другой директории. Collector получил служебное уведомление о закреплении и возобновился по сохранённому offset. Полная приёмка продолжается: медиа, два бота/чата, внешние публикации/правки через collector и нативные клиенты ещё не проверены. Критерии:

1. Подключить два бота и два тестовых чата; проверить права и переменные среды.
2. Из другого проекта выполнить inventory/inspection в каждом клиенте.
3. По команде человека отправить, отредактировать, закрепить/открепить и удалить сообщение; сверить видимый результат и message_id.
4. Повторить успешный request_id, подтвердить отсутствие дубля.
5. Получить через collector сообщение и правку, проверить архив/статистику и возобновление по offset.
6. Проверить readonly, второй сборщик, webhook conflict и отсутствие секретов в ответах.
7. Загрузить нативные пакеты в Codex/Claude Code, подтвердить skill и tools. Проверка манифеста не доказывает загрузку.

## 2. Установка и публикации

Перед расширением публикаций — подключение и управление аккаунтами по [ACCOUNT_CONTROL.md](ACCOUNT_CONTROL.md): ссылки добавления бота; локальная пользовательская авторизация и сохранённые сессии; отдельные account permissions; автоматическое подключение ботов; создание группы/канала и managed bot; публичные настройки ботов и модерация. Это согласованное направление следующего этапа, ещё не реализованное в 0.2. Каждый шаг имеет отдельный рабочий сценарий и приёмку.

Установщик с preview и сохранением MCP-настроек; управление темами; интеграция credential store с защитой ОС; фоновый collector с автостартом. Локальные файлы, альбомы, подписи/медиа-редактирование, ответы, форматирование, ссылки. Разрешение unknown/pending с доказательством исхода, без скрытого retry.

## 3. Инспекция

Экспорт, coverage интервалы/gaps, аналитика доступных реакций, отчёты с источниками. Authenticated webhook ingestion для существующих ботов. Развитие ACL за пределы workspace-политик, retention/backup/delete локальных данных. Панель настройки использует тот же service layer.

## 4. История и автономность

При необходимости старой истории — расширение optional MTProto account adapter с отдельными правами чтения истории; публикации продолжают идти ботами. Отложенные публикации и автоматизация требуют правил человека, дедупликации и audit. Для облачных чатов — защищённый remote MCP gateway.

Открытые решения: старая история, хранение персональных сообщений, объём модерации, интерфейс настройки. Они не блокируют Bot API MVP и не считаются реализованными.
